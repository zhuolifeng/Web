一、设计方案概述
--------------------------------------------------------------------------------

本次作业将原有的"猪猪书城"静态网站重构为基于 React 和 React Router 的单页应用（SPA）。
主要实现了书籍列表页面与书籍详情页面之间的路由跳转，并通过 URL 参数传递书籍 ID，
实现页面间的数据关联。


二、React 构件式开发原则的遵循
--------------------------------------------------------------------------------

1. 单一职责原则（Single Responsibility Principle）

   每个 React 组件都只负责一个功能领域：
   - Header 组件：仅负责渲染顶部导航栏和 logo
   - Footer 组件：仅负责渲染页脚内容
   - BookCard 组件：仅负责渲染单本书籍的卡片展示
   - BookList 组件：仅负责渲染书籍列表网格
   - BookDetailPage 组件：仅负责渲染书籍详情页面
   - Layout 组件：仅负责提供统一的页面布局结构

   这种设计使得每个组件职责明确，易于理解和维护。


2. 组件复用原则（Reusability）

   - BookCard 组件设计为纯展示组件，通过 props 接收书籍数据，可以在任何需要展示
     书籍卡片的地方复用。
   - Layout 组件封装了页面通用结构（Header、Footer、main），所有页面组件都通过
     Layout 包裹，避免了代码重复。
   - Header 组件中的导航链接使用 NavLink，支持自动添加 active 样式，无需父组件干预。


3. 组合优于继承原则（Composition over Inheritance）

   - 采用组合模式：BookList 通过 map 函数组合多个 BookCard 组件
   - Layout 组合模式：通过 children prop 将页面内容嵌入到统一的布局结构中
   - 未使用任何继承关系，所有组件都是函数组件，通过 props 和 composition 实现功能扩展


4. 最小化 props 原则（Minimizing Props）

   - BookCard 仅接收必要的 book 数据作为 props
   - BookList 接收 books 数组，由其内部负责渲染每个 BookCard
   - 组件间数据传输简洁清晰，避免了不必要的 props 传递


5. 状态管理本地化原则

   - BookDetailPage 中的 quantity（数量）状态是组件内部状态，不影响其他组件
   - 使用 React 的 useState Hook 管理组件内部状态
   - 状态变更通过受控组件模式实现（value + onChange）


三、工程结构的组织
--------------------------------------------------------------------------------

项目采用标准的 Create React App 目录结构，并参考样例代码 se2321_10_reactrouter 的组织方式：

    bookstore-react/
    ├── public/
    │   └── index.html          ← HTML 入口文件
    │
    ├── src/
    │   ├── components/         ← 可复用组件目录
    │   │   ├── Header.js      ← 顶部导航栏组件
    │   │   ├── Footer.js      ← 页脚组件
    │   │   ├── Layout.js      ← 页面布局组件
    │   │   ├── BookCard.js    ← 书籍卡片组件
    │   │   └── BookList.js    ← 书籍列表组件
    │   │
    │   ├── pages/             ← 页面组件目录
    │   │   ├── HomePage.js    ← 首页（书籍列表）
    │   │   ├── BookDetailPage.js ← 书籍详情页
    │   │   ├── CartPage.js    ← 购物车页
    │   │   ├── LoginPage.js   ← 登录页
    │   │   └── OrderPage.js   ← 订单页
    │   │
    │   ├── Data.js            ← 数据文件（类似样例中的 Data.js）
    │   ├── App.js             ← 根组件与路由配置
    │   ├── index.js           ← 应用入口文件
    │   └── index.css          ← 全局样式文件
    │
    ├── package.json          ← 项目依赖配置
    └── README.md              ← 项目说明文档

结构设计理由：

1. components/ 与 pages/ 分离
   - components/ 存放纯 UI 组件，不涉及业务逻辑，可跨页面复用
   - pages/ 存放页面级组件，代表路由中的一个页面，与 URL 路径一一对应
   - 这种分离使得组件职责清晰，便于团队协作和代码维护

2. 数据文件独立
   - Data.js 集中管理所有书籍数据，模拟后端 API 返回的数据结构
   - 提供 getBookById 辅助函数，方便获取单本书籍信息
   - 类似样例 se2321_08_react_bookbrowser 中的 Data.js 设计

3. 路由配置集中管理
   - App.js 中集中配置所有路由映射关系
   - 使用 React Router v6 的 Routes/Route 组件
   - 动态路由参数（如 /book/:id）实现页面间数据传递


四、关键技术实现
--------------------------------------------------------------------------------

1. 路由跳转与数据传递
   - 使用 React Router 的 useParams Hook 获取 URL 中的书籍 ID
   - Link 组件实现声明式导航，避免使用传统的 <a> 标签
   - URL 参数设计：/book/:id，例如 /book/4 对应"三体"书籍详情

2. 页面状态管理
   - React State 管理组件内部状态（如购买数量）
   - Props 传递父组件数据给子组件
   - 通过 URL 参数实现跨页面数据传递

3. 错误处理
   - BookDetailPage 中对无效书籍 ID 进行处理
   - 显示友好的"书籍不存在"提示，并提供返回首页的链接


五、与样例代码的对比
--------------------------------------------------------------------------------

参考样例 se2321_10_reactrouter：
- 借鉴了其目录结构：routes/ 文件夹的组织方式
- 学习了其路由配置方式：createBrowserRouter + children 嵌套路由
- 采用了类似的数据传递模式：通过 loader 获取数据

参考样例 se2321_08_react_bookbrowser：
- 借鉴了 Data.js 集中管理数据的模式
- 学习了两个主页面（列表+详情）的设计思路
- 采用了类似的组件拆分方式：Excel 组件对应 BookList，BookCard 单独抽取


六、可维护性与可扩展性
--------------------------------------------------------------------------------

1. 可维护性
   - 每个组件文件行数控制在 100 行以内，职责单一
   - 组件命名清晰，符合 React 社区约定俗成的命名规范
   - 样式文件独立维护，不影响组件逻辑

2. 可扩展性
   - 添加新页面只需在 pages/ 创建新文件，并在 App.js 添加路由即可
   - 添加新组件只需在 components/ 创建文件，然后在需要的地方引用
   - 书籍数据在 Data.js 中集中管理，扩展数据只需修改该文件
   - 未来可通过添加 Context 或状态管理库（如 Redux/Zustand）扩展全局状态管理


七、总结
--------------------------------------------------------------------------------

本次重构严格遵循了 React 构件式开发的核心原则：
1. 函数式组件 + Hooks 替代类组件
2. 单一职责，每个组件功能明确
3. 组件复用，通过 Props 传递数据
4. 组合优于继承
5. 清晰的项目结构，便于维护和扩展

工程结构参考了课程提供的两个样例代码，吸收了它们的优点，形成了一套适合小型
Web 应用开发的工程组织方案。该方案具有良好的可维护性和可扩展性，可以作为
后续迭代开发的基础。
